### [REQ-20260519-001] AI 起草邮件正文支持语言选择

- 提出时间：2026-05-19
- 需求内容：在「回复邮件」「撰写邮件」「转发邮件」三个场景中，与 AI 生成正文按钮（自动回复 / 自动生成 / 自动撰写转发备注）紧邻处，增加一个语言下拉框，候选项为「中文」「英文」，默认值为「中文」。生成的邮件正文必须严格按用户当前所选语言输出，不再自动判别原邮件 / 用户意图语言。
- 目标：避免「明明用中文写意图却输出英文（或反之）」的语种漂移，让用户对 AI 起草结果的语言完全可控。
- 验收标准：
  - 三个面板（auto_reply_panel / auto_compose_panel / auto_forward_panel）的 ✨ 生成按钮旁均有「中文 / 英文」下拉框，默认中文
  - 转发模式下新增 auto_forward_panel；该面板只在 forward 模式可见
  - 后端 `ReplyGenerationRequest` 与 `ComposeDraftRequest` 模型接受 `language ∈ {"zh","en"}`，缺省 `"zh"`
  - 生成结果的整体语言（称呼 + 正文 + 结尾）严格匹配所选值；不会因为意图或原邮件语种而漂移
  - 每次重新打开撰写窗口时，三个下拉框都重置为「中文」
- 当前状态：已完成

### [REQ-20260519-002] 新增「曾经重要」文件夹

- 提出时间：2026-05-19
- 需求内容：在左侧文件夹列表中「重要」下方新增一个「曾经重要」条目。凡是被标为重要的邮件，在点击「✓ 已处理」后不再消失，而是落进「曾经重要」视图。
- 目标：保留 LLM 经验沉淀所依赖的 important 信号（之前点已处理会同时清掉 important，导致经验失锚），同时把"待我处理"和"已经处理过"的重要邮件在视觉上分开。
- 验收标准：
  - 左侧栏顺序：⭐ 重要 → ✓ 曾经重要 → ✦ 全部 →（各分类）
  - ⭐ 重要 视图过滤改为 `important && !handled`（只看待处理）
  - ✓ 曾经重要 视图过滤为 `important && handled`
  - 各分类文件夹的红色 ★ 徽章仅统计待处理重要邮件
  - 详情页 / 列表行 / 右键菜单的「✓ 已处理」按钮在 `handled==true` 时隐藏，避免重复点击
  - 取消重要时同时清掉 handled（既退出 重要 也退出 曾经重要）
  - 后端 `/api/emails/{id}/update` 在 `handled=true` 时保留 important（修复历史 bug）
  - `docs/USER_GUIDE.md` 第 9 节同步更新
- 当前状态：已完成（历史数据无法回填——修复前点过「已处理」的邮件 important 已被错误清掉，进不了曾经重要；可手动重新标记重要救回）

### [REQ-20260519-003] 修复经验对话框「直接移动」按钮卡死

- 提出时间：2026-05-19
- 需求内容：通过右键菜单 / 拖拽 / 「📁 移动到 ▾」打开经验对话框时，「直接移动」按钮经常停留在「移动中…」灰色状态、无法点击。要求该按钮稳定可用。
- 目标：用户每次打开经验对话框都能直接走"跳过经验"路径，不被前一次操作残留的 UI 状态卡住。
- 验收标准：

  - `closeRecategorizeModal` 和 `closeImportanceModal` 同样兜底重置 skip/submit 按钮状态
  - 反复点开同一对话框 N 次，「直接移动」/「直接标为重要」/「直接取消重要」按钮始终为初始可点状态
- 当前状态：已完成

### [REQ-20260519-006] 避免重复收取 + 状态栏显示邮件日期

- 提出时间：2026-05-19
- 需求内容：当扩大「收取天数」窗口（如 5 → 10 天）时，已经收过的近 5 天邮件不应再被重复 FETCH / LLM 分类一遍。同时在收取过程中，状态栏需显示当前正在收取的邮件的日期。
- 目标：消除"扩窗口 → 全量重拉"造成的带宽 / LLM Token 浪费；让用户直观看到收取进度推进的时间窗口。
- 验收标准：
  - `receive_emails` 接受 `known_uids: Optional[set]` 参数
  - SEARCH 返回后、进入 per-email FETCH 循环前，剔除 `known_uids` 中的 UID
  - `planned` 事件新增 `already_known` 字段，前端显示「（跳过已存的 K 封）」
  - `classified` 事件新增 `received_at`（ISO-8601 UTC），前端转本地 `YYYY-MM-DD` 显示「已分类 5/N 2026-05-15：[分类] 主题…」
  - `/api/receive` 与 `/api/receive/stream` 入口处按 `account_id` 构建 `known_uids`
- 当前状态：已完成

### [REQ-20260519-007] 收取邮件实时进度提示 + 每 10 封刷新列表

- 提出时间：2026-05-19
- 需求内容：收取邮件过程中状态栏要实时显示"第 X / 共 N 封"；每完成 10 封要刷新一次邮件列表，让用户能立即看到新拉回的邮件。
- 目标：让用户知道系统在工作、还要多久、并且不必等完全结束就能开始阅读已经拉回的邮件。
- 验收标准：
  - 状态栏在收取过程中实时滚动「已分类 X/N：[分类] 主题…」
  - 「收取邮件」按钮文字同步显示「收取中 X/N…」
  - 每 10 封触发一次 `refreshAll()`，UI 上能立即看到新增邮件
  - 排查并修复根因：Starlette `GZipMiddleware` 使用 `gzip.GzipFile.write()` 缓冲流式 NDJSON。将所有 `/stream` 端点加入 `skip_prefixes`，让每条事件立刻到达浏览器
- 当前状态：已完成

### [REQ-20260519-008] 修复扩大 fetch_days 后无法拉取更早邮件

- 提出时间：2026-05-19
- 需求内容：将「拉取近 X 天」从 14 天改为 60 天后，期望系统补拉 15-60 天范围内的邮件；实际表现是仍然只看到原来 14 天内的邮件。要求扩大窗口后能正确拉到更早的邮件。
- 目标：让 fetch_days 的语义"诚实"——用户调大数字就一定能看到更早的历史邮件，不会被沉默地丢弃。
- 验收标准：
  - 在 sync_state 中持久化 `fetch_days_at`（watermark 当时覆盖的天数）
  - 当 `current_days > stored.fetch_days_at` 或 `fetch_days_at` 缺失（旧数据迁移情形）时，识别为 widened 模式：丢弃 UID watermark 过滤，改用 `SINCE <new_cutoff>`
  - 由 Message-Id 去重 + REQ-20260519-006 的 known_uids 过滤共同保证不重复处理
  - sync_meta 返回 `fetch_days_at = max(stored, current_days)`；watermark 不回退（`max(prior, seen)`）
  - 状态栏区分「新邮件」vs「邮件」以反映 incremental vs widened/initial 模式
- 当前状态：已完成

### [REQ-20260519-009] 后台运行 + 双击启动/停止脚本 + 关闭后端按钮

- 提出时间：2026-05-19
- 需求内容：当前调试系统需要一直开着 Terminal 窗口跑 uvicorn。希望能让后端跑在后台，不必常开 Terminal。同时希望有"一键启动"的方式（最好双击运行），并在系统管理页加一个按钮可关闭后端进程；用户指南里写清楚启动 / 关闭流程。
- 目标：把日常使用门槛降到"双击即可"，不再依赖 Terminal 操作。
- 验收标准：
  - `scripts/start.command` 可双击运行；自动激活 `.venv`、`nohup` 起 uvicorn、写 PID 文件、自动打开浏览器、Terminal 窗口关闭后后端继续运行
  - `scripts/stop.command` 可双击运行；通过 PID 文件优雅停止（SIGTERM → SIGKILL fallback），PID 文件缺失时通过 `lsof` 端口反查兜底
  - `/admin` 页新增「关闭后端」卡片与按钮，调用 `POST /api/system/shutdown`（admin-only）；后端收到后返回 200 再 SIGTERM 自己（让 HTTP 响应能 flush）
  - 启动脚本能检测：端口被占 / 已有实例在跑 / 缺 `.venv` / 缺依赖，每种都给出明确提示
  - `docs/USER_GUIDE.md` 新增第 0 节「启动与关闭系统」，含 macOS 首次双击的"身份不明的开发者"提示、常见故障排查表
- 当前状态：已完成
